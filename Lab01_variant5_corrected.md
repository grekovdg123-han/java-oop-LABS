# 5. Краткий теоретический конспект

## 5.1. Класс и объект

**Класс** — шаблон для создания объектов. Он определяет данные объекта и методы работы с ними.

В этой работе класс `Apartment` содержит данные квартиры:

- идентификатор;
- адрес;
- площадь;
- количество комнат;
- цену.

**Объект** — конкретный экземпляр класса.

```java
Apartment ap = new Apartment();
```

Здесь `Apartment` — класс, а `ap` — объект.

---

## 5.2. Модификаторы доступа

Модификаторы доступа определяют, откуда разрешено обращаться к полям и методам.

| Модификатор                          | Доступ                                     |
| ------------------------------------ | ------------------------------------------ |
| `public`                             | Из любого места программы                  |
| `protected`                          | Из того же пакета и из классов-наследников |
| без модификатора (`package-private`) | Только внутри того же пакета               |
| `private`                            | Только внутри самого класса                |

Поля `Apartment` объявлены как `private`, поэтому напрямую изменить их извне нельзя.

---

## 5.3. Инкапсуляция

**Инкапсуляция** — принцип ООП, при котором данные объекта скрываются от прямого изменения, а доступ к ним выполняется через методы класса.

Например:

```java
private double area;
```

Для изменения площади используется setter:

```java
public void setArea(double area) {
    if (area <= 0) {
        throw new IllegalArgumentException("Площадь должна быть больше 0");
    }
    this.area = area;
}
```

Так объект не позволяет сохранить некорректную площадь.

---

## 5.4. Ключевое слово `this`

`this` — ссылка на текущий объект.

```java
this.price = price;
```

Здесь:

- `this.price` — поле текущего объекта;
- `price` — параметр метода.

---

## 5.5. Классы-обёртки и автоупаковка

Для примитивных типов существуют классы-обёртки.

| Примитив  | Класс-обёртка |
| --------- | ------------- |
| `int`     | `Integer`     |
| `long`    | `Long`        |
| `double`  | `Double`      |
| `boolean` | `Boolean`     |
| `char`    | `Character`   |

**Автоупаковка** — автоматическое преобразование примитива в объект класса-обёртки.

```java
Integer number = 10;
```

**Автораспаковка** — обратное преобразование:

```java
int value = number;
```

## 6.2. `Apartment.java`

В исправленной версии:

- устранено неправильное сообщение в `setArea()`;
- исправлена формулировка проверки комнат;
- уточнено сообщение в `setPrice()`;
- добавлена защита от `status == null`;
- формат цены приведён к двум знакам после запятой;
- `getDescription()` сохранён в формате варианта 5;
- выровнены отступы и пробелы.

```java
package com.mycompany.lab01;

public class Apartment {

    private long id;
    private String address;
    private double area;
    private int rooms;
    private double price;
    private ApartmentStatus status;

    public long getId() {
        return id;
    }

    public String getAddress() {
        return address;
    }

    public double getArea() {
        return area;
    }

    public int getRooms() {
        return rooms;
    }

    public double getPrice() {
        return price;
    }

    public ApartmentStatus getStatus() {
        return status;
    }

    public void setId(long id) {
        if (id <= 0) {
            throw new IllegalArgumentException("ID должен быть больше 0");
        }
        this.id = id;
    }

    public void setAddress(String address) {
        if (address == null || address.isBlank()) {
            throw new IllegalArgumentException("Адрес не может быть пустым");
        }
        this.address = address;
    }

    public void setArea(double area) {
        if (area <= 0) {
            throw new IllegalArgumentException("Площадь должна быть больше 0");
        }
        this.area = area;
    }

    public void setRooms(int rooms) {
        if (rooms < 1 || rooms > 10) {
            throw new IllegalArgumentException(
                    "Количество комнат должно быть от 1 до 10"
            );
        }
        this.rooms = rooms;
    }

    public void setPrice(double price) {
        if (price <= 0) {
            throw new IllegalArgumentException("Цена должна быть больше 0");
        }
        this.price = price;
    }

    public void setStatus(ApartmentStatus status) {
        this.status = status;
    }

    public String getStatusMessage() {
        if (status == null) {
            return "Статус не задан";
        }

        switch (status) {
            case FREE:
                return "Свободна — доступна для покупки";
            case SOLD:
                return "Продана — недоступна";
            case RENTED:
                return "Сдана в аренду";
            default:
                return "Статус неизвестен";
        }
    }

    public String getDescription() {
        return String.format(
                "Квартира по адресу %s: %.1f м², %d комн., цена %.2f руб.",
                address, area, rooms, price
        );
    }
}
```

# 7. Контрольные вопросы

## 1. Что такое класс и объект? В чём их различие?

**Класс** — шаблон для создания объектов. Он определяет, какие данные и методы будут у объекта.

Например, `Apartment` — класс, который описывает квартиру.

**Объект** — конкретный экземпляр класса.

```java
Apartment ap = new Apartment();
```

`Apartment` — класс, `ap` — объект этого класса.

---

## 2. Какие модификаторы доступа существуют в Java?

В Java есть четыре уровня доступа:

- `public` — доступ из любого места;
- `protected` — доступ внутри пакета и в классах-наследниках;
- без модификатора (`package-private`) — доступ только внутри пакета;
- `private` — доступ только внутри самого класса.

В этой работе поля `Apartment` объявлены как `private`.

---

## 3. Что такое инкапсуляция? Зачем она нужна?

**Инкапсуляция** — принцип ООП, при котором данные объекта скрыты от прямого изменения извне, а работа с ними выполняется через методы.

Она нужна для:

1. защиты данных;
2. проверки значений;
3. контроля доступа;
4. упрощения изменения и сопровождения программы.

Например, площадь меняется не напрямую, а через `setArea()`, который проверяет значение.

---

## 4. Чем конструктор отличается от обычного метода?

**Конструктор** используется при создании объекта и его начальной инициализации.

```java
Apartment ap = new Apartment();
```

**Обычный метод** работает с уже созданным объектом.

```java
ap.setPrice(8500000);
```

| Конструктор                     | Обычный метод                             |
| ------------------------------- | ----------------------------------------- |
| Вызывается при создании объекта | Работает с существующим объектом          |
| Имя совпадает с именем класса   | Может иметь любое допустимое имя          |
| Тип возврата не указывается     | Может возвращать значение или быть `void` |

---

## 5. Для чего используется ключевое слово `this`?

`this` — ссылка на текущий объект.

```java
public void setAddress(String address) {
    this.address = address;
}
```

Здесь `this.address` — поле объекта, а `address` — параметр метода.

---

## 6. Что такое классы-обёртки? Что такое автоупаковка?

Классы-обёртки позволяют использовать примитивные значения как объекты.

Примеры:

- `int` → `Integer`;
- `long` → `Long`;
- `double` → `Double`;
- `boolean` → `Boolean`.

**Автоупаковка:**

```java
Integer number = 10;
```

**Автораспаковка:**

```java
int value = number;
```

---

## 7. Почему прямой доступ к полям класса считается плохой практикой?

Если сделать поле `public`, внешний код сможет изменить его без проверки.

```java
public double area;
```

Тогда можно записать:

```java
ap.area = -50;
```

и получить некорректное состояние объекта.

Поэтому поля обычно делают `private`, а изменение выполняют через setter-методы.

Это позволяет:

1. проверять значения;
2. защищать состояние объекта;
3. сохранять инкапсуляцию;
4. легче изменять внутреннюю реализацию класса.

---

## 8. Какие преимущества даёт ООП по сравнению с процедурным программированием?

В процедурном программировании данные и функции в основном разделены.

В ООП связанные данные и методы объединяются в объектах.

Основные преимущества ООП:

1. удобное представление предметной области через объекты;
2. инкапсуляция и защита данных;
3. повторное использование кода;
4. возможность расширения программы;
5. более удобное сопровождение большого проекта;
6. использование наследования, композиции и полиморфизма.
